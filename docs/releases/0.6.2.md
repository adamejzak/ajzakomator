# ajzakomator 0.6.2

- New: make a saved Claude account the main one. In the AI account limits panel, open the menu of a saved Claude account and choose "Make main account". The current main login is kept as a saved account and the selected one becomes the login that Claude Code uses, without closing your sessions. Open sessions normally pick up the new login on their next message (this depends on the Claude Code version; a session that does not can be restarted and resumed). Windows and Linux only; the option is hidden on macOS.
- The swap exchanges the two logins instead of copying them, because Claude refresh tokens rotate and two live copies of one login would invalidate each other. Other data in your Claude files (for example MCP logins) is left untouched. The app refreshes the selected account's token with Anthropic before swapping, writes every file atomically, checks that Claude Code did not change the login files meanwhile, and rolls back on any error.
- If a swap or the app is interrupted, the next start repairs the state when it can be proven safe. Otherwise nothing is changed, further swaps are blocked and a warning appears in the panel with a "Clear warning" button; you may then need to sign in again to an account that stopped working. A Claude login can always be redone.
- A swap takes about 3 seconds and shows a progress indicator on the card. Account removal and re-login are refused while a swap is running or unresolved.
- Known limit: if a Claude session writes its login files in the very same millisecond as the swap replaces them, this cannot be detected without a lock shared with Claude Code. Keep your own backup of `~/.claude/.credentials.json` and `~/.claude.json` before the first swap.

Validated with type checks, unit tests, a production build, simulated crashes and concurrent Claude token refreshes at every step, and real Electron runs of swapping, refusals, interrupted-swap recovery and warnings on a fake home with fake tokens. Real Claude Code sessions with two accounts were not tested.
