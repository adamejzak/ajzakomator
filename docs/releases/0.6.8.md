# ajzakomator 0.6.8

- Updates are one smooth flow with one window. The status bar shows "Dostępna wersja X - Aktualizuj", "Pobieranie X... N%", "Wersja X gotowa - Zainstaluj" and "Instalowanie X..." (no more "restart" wording), and clicking always opens a single update window that joins a running download, installs and relaunches. The target is always the newest release: if a newer version appears while an update is offered, downloading, ready or while the startup question is open, everything moves to it; an older or stale answer from the feed is ignored; once the installer has been handed over that version finishes and the newer one is offered on the next start. The startup question, the status bar window and the update window can no longer show up at the same time, and a leftover record of the running version no longer silently skips the next startup question. macOS follows the same rules.
- Saved Claude accounts no longer end up with "could not read the limits" because of HTTP 429 from the token endpoint: refresh requests use the app's own User-Agent, headers are fully controlled, a rate limit is followed by a hard backoff that survives restarts, and the card has a "Sign in again" action for that case.
- Terminal garbage after a CLI dies is fixed. When Claude or Codex exits or is killed, the mouse, focus and bracketed-paste modes are switched off again (also after Ctrl+C), so moving the mouse no longer prints `[555;77;38M...` into the shell. There is a new "Zresetuj terminal" action in the cell menu and the command palette, and a safety valve that stops forwarding mouse reports to a shell that is echoing them.
- Files: rename (double click, F2 or context menu), drag and drop to move, Ctrl+C / Ctrl+X / Ctrl+V of files and folders (Ctrl while dropping copies), duplicate, new file and folder, delete to the system trash with confirmation, undo of the last rename or move, and conflict handling (replace, keep both, skip). Open editor tabs follow renames and moves and unsaved drafts are never dropped. The tab bar scrolls (wheel and arrows) with an "all tabs" list, and tabs have a menu: Close, Close others, Close to the right, Close all, Copy path, Show in file manager and Locate in Files.
- MCP uses far fewer tokens: the tool list is about 50% smaller for coordinators and 70% smaller for workers, results are compact, workers only see the tools they can use, and a new `wait_for` tool replaces polling. Schemas no longer use `$ref` (Codex passed them on unresolved), Codex asks for approval for tools that send text to other agents or change an agent's profile, and a worker can no longer read other agents' task results or change its own profile. Verified with the real Claude Code and Codex clients.
- Performance: sessions of the active project are loaded in the background after the window appears (Settings: visible, project or all, default project, at most 12 background cells per launch), terminals no longer recalculate styles when hidden, the state is synchronised with small patches instead of full copies (about 35 times fewer bytes per edit), and the editor, settings and automation screens load on demand (the main bundle is 40% smaller). A lost patch can no longer leave the screen out of sync.

Validated with type checks, unit and fault-injection tests, a production build from a clean `npm ci`, a real packaged Windows installer in a lab (layout, lazy screens, terminals, files, background loading), real update runs against a local feed (manual and automatic modes, a newer version appearing mid-update, a stale feed answer) and real Claude Code and Codex clients against the MCP server. macOS behaviour, the real GitHub feed, UAC installs and deleting files to the real recycle bin were not tested.
