# ajzakomator 0.5.10

- Fixed a "JavaScript error occurred in the main process: Object has been destroyed" dialog that could appear when the app was started again while the previous process was still shutting down, for example right after an update. A blocked dialog like this also stalled the update window and delayed the installer. Windows that were already closed are no longer touched, and the app no longer shows a blocking error dialog while it is closing or updating.
- The update window can now be closed with the X button or Escape. Before the installer starts, closing it cancels the update and opens the app; once the installer is running it only hides the window and the update continues in the background.
- The update progress is honest: it no longer climbs to 88% by itself. It shows "Waiting for ajzakomator to close...", "Waiting for the installer..." and "Installation is taking longer than usual..." when that is the real state.
- The shutdown has a hard time limit, and the handoff to the installer is guarded, so a stuck shutdown cannot keep the installer waiting. A launch attempted during shutdown is repeated afterwards instead of being lost.
- A failed update download is no longer retried in the background on every start while the retry pause is active, and the update window text no longer promises an automatic restart when the update is installed on close.

Validated with type checks, unit tests, a production build and a real end-to-end update test: local installers for two versions, a local update feed, the startup update check, the status bar update button, closing and restarting the app repeatedly during an update, cancelling the update window, offline and failing feeds, and a clean uninstall.
