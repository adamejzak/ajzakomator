ajzakomator 0.4.0 adds optional MCP integration for Claude Code and Codex agents.

- New grids default to **No MCP**. Choose a coordinator or worker role only for cells that should use automation; ordinary terminals and startup prompts continue to work independently.
- The **AI** panel shows agents, roles, tasks, structured results, messages and recent activity. Tasks and messages persist across app restarts.
- Coordinators can create background grids with startup tasks, presets and isolated git worktrees, without switching your active tab.
- Agents can read their inbox, report task results, exchange project messages and create reusable prompt snippets.
- MCP uses a local authenticated server with separate credentials per cell and project-scoped access. You can disable access or pause automation from the app.
- Concurrent UI and agent changes are synchronized without replacing each other's grids, snippets or tasks.

Tasks and messages use an MCP inbox. Automatic queue delivery is available for running Codex sessions explicitly selected from history, with a Codex version that supports `codex queue`. Claude and unverified Codex sessions can read their MCP inbox or receive a manually pasted prompt. Cancelling a task does not interrupt the model.

Po polsku: **role i MCP są opcjonalne** — nowy grid domyślnie działa bez integracji. Panel **AI** umożliwia zarządzanie zadaniami, wynikami i wiadomościami. Koordynator może tworzyć gridy w tle, a wykonawcy odbierać zadania i raportować wyniki. [Instrukcja MCP](https://github.com/adamejzak/ajzakomator/blob/v0.4.0/docs/MCP.md).
