# unimux 0.9.3

- **Cells come back after a terminal process crash.** When the background process that runs the terminals restarts, your Claude, Codex and shell cells start again by themselves instead of staying blank. An SSH stream error no longer takes every other terminal down with it.
- **A crashed or frozen window recovers.** If the app window crashes (for example out of memory in a large grid), it reloads by itself and picks up the running terminals with their output. After several crashes in a minute, or when the window stops responding, the app asks whether to reload, wait or quit.
- **One broken part no longer blanks the window.** A cell, the side panel, the status bar or a dialog that fails to draw shows a small card with Try again, and the rest of the app keeps working. Grids with a damaged saved layout are repaired when the app starts.
- **Repeated terminal crashes.** After the terminal process crashed several times in a row, the app offers Restart terminals or Quit (without freezing the app behind the message), and cells say why they cannot start.
- **Safer saving.** The app state is saved atomically, flushed to disk and retried when antivirus, indexing or OneDrive holds the file for a moment; a failed save is kept and tried again instead of being lost. A damaged state.json is kept next to it as a backup, and the backup copy is refreshed every hour. Changes from the last moments are also saved when Windows signs out or shuts down.
- **Clear start failures.** If unimux cannot start, it shows the reason and exits instead of staying invisible in the background (where later launches did nothing). It also starts when the local hook server is blocked.
- **A cell that cannot start says why.** A failed start (for example a locked or full disk) shows its error in the cell instead of leaving it blank.
- **Clean quit.** Terminals that do not end in time when you quit are stopped together with the programs they started.
- **macOS: Cmd+Q and the Edit shortcuts.** The app has a minimal menu again, so Cmd+Q quits and copy, paste, cut, select all and undo work in text fields.
- **Crash log.** Errors of the app (also from the window and the terminal process) are written to `crash.log` in the app data folder, so problems can be traced.
